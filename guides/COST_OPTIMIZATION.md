# صرفه‌جویی در Cursor Cloud و Codex

**اصل:** همه فایل‌های هدف الزاماً اجرای جداگانه Cloud یا Codex نیست. این بسته پرامپت مستقل به‌ازای هر فایل می‌دهد؛ تیم‌ها می‌توانند کارهای کم‌ریسک و غیرمتداخل را پس از بررسی محدوده در یک اجرای عامل گروه کنند.

## نخستین صرفه‌جویی عملی
- ۳۰ ممیزی JSON Schema در ۶ پرامپت گروهی (`prompts/00_BOOTSTRAP/CONTRACT_AUDIT_BATCH_01.md` تا 06)؛ هرکدام ۵ فایل خروجی مستقل. ارجاعات اصلی در پرامپت‌های فردی باقی می‌مانند.
- برای Gateها فقط یک اجرای مستقل Codex در انتهای هر مرحله کافی است؛ نه الزاماً یک review گران برای تمام فایل‌ها.
- کارهای UI کوچک را با Grok Local انجام بده؛ وقتی آزمون بصری و مرورگر مهم است Cloud را بی‌دلیل مصرف نکن.
- برای موارد وابسته به APIهای تأییدنشده و CMS مجهول، فقط Mock یا interface بساز؛ از agent برای جست‌وجوی بی‌پایان API ساختگی استفاده نکن.
- دو تسک با فایل مشترک را در یک زمان اجرا نکن؛ حداکثر ۲–۳ شاخه موازی مستقل.
- در تسک‌های sensitive (RBAC، private reports، publishing dispatcher، migrations، bridge) مدل مناسب را برای کد و آزمون مسیرهای خطا انتخاب کن.
- برای تست واحد، ابتدا fixture محلی و شبیه‌ساز provider/adapters؛ فراخوانی AI پولی یا انتشار واقعی جزء این مرحله نیست.

**محدودیت:** هزینه و دسترسی مدل‌ها به حساب واقعی Cursor مربوط است و این بسته هیچ هزینه یا سقف استفاده‌ای را تأیید نکرده است.
